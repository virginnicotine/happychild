HAPPYCHILD · пакет обновлений (16 октября 2026)

УСТАНОВКА
1. Сделайте резервную копию файлов и экспорт данных Supabase перед изменениями.
2. Распакуйте архив в корень happychild с заменой совпадающих файлов.
3. Из папки проекта: git status --short
4. Проверьте изменения: git diff --check; git diff --stat
5. Если всё устраивает: git add -A && git commit -m "Refine catalog and unify user cabinet" && git push origin main
6. Дождитесь успешных SourceCraft install-deps/build-site/publish-site.

ВАЖНО: SUPABASE EDGE FUNCTION НЕ РАЗВОРАЧИВАЕТСЯ ОТ PUSH SOURCECRAFT.
В этом пакете изменён supabase/functions/site-api/index.ts, который нужно отдельно развернуть через Supabase CLI / Supabase Dashboard.
Команда при установленном и авторизованном Supabase CLI, из корня проекта:
  supabase functions deploy site-api
Проверьте, что функция использует нужный проект и сохранены переменные окружения. Не выкладывайте service_role ключ в сайт.

Существующие таблицы public.profiles, public.complaints, public.warnings и public.audit_logs должны существовать (они уже используются прежним site-api).
Новое API: submit_complaint и my_dashboard. Они определяют пользователя по проверенному JWT и не принимают чужой author_id.
ВНИМАНИЕ: Старые жалобы, оставшиеся ТОЛЬКО в localStorage пользователей, автоматически не перенесены в Supabase. Нужен отдельный управляемый перенос, если их важно сохранить.

Что проверить вручную на опубликованном сайте:
- обычный сотрудник видит кабинет, только свои жалобы и предупреждения;
- администратор видит общие обращения и управление ролями;
- заблокированный пользователь получает уведомление при входе; прямые запросы к API запрещены;
- новая жалоба появляется в админке и кабинете автора;
- PDF открывается новой вкладкой; зеркало DXF в отдельном разделе;
- карточки лестниц/горок/панелей/досок/парковой мебели распределены правильно.

В архив не входят изображения, DXF, PDF и рабочие данные Supabase.
