СЧАСТЛИВЫЙ РЕБЁНОК / интеграционный тестовый комплект

ВАЖНО: НЕ ПУБЛИКУЙТЕ ЭТУ ВЕРСИЮ ВМЕСТО РАБОЧЕЙ БЕЗ ТЕСТИРОВАНИЯ.
1. Настройки уже прописаны в supabase-config.js (только публичный ключ).
2. Edge Function: supabase/functions/site-api/index.ts — разместить через Supabase CLI либо Dashboard Edge Functions.
   Требует серверные секреты SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY, автоматически доступные в стандартном Supabase Edge окружении. НЕ копировать service_role на сайт.
   Для функции отключена встроенная проверка JWT (verify_jwt=false): она самостоятельно проверяет сессии для административных запросов. Публичный endpoint login требует отдельного rate limiting/WAF перед промышленным запуском.
3. SQL первого этапа уже запущен. Никаких дополнительных SQL в этом архиве нет.
4. Зарегистрировать свой аккаунт, подтвердить email, затем в SQL Editor:
   update public.profiles set role = 'admin' where login = 'ВАШ_ЛОГИН';
5. Первый администратор не создаётся автоматически.
6. Старые ЛОКАЛЬНЫЕ аккаунты сотрудников можно перенести в исходном браузере (проверяется старый пароль). Сохраняется только имя и логин, если логин не занят; права admin/manager не переносятся. После ввода email подтвердить письмо. Не удаляйте localStorage до завершения переноса.
7. Старые пароли админов из JS больше не работают. Если учётка сохранилась только на другом браузере/компьютере, перенос невозможен без него.
8. Пока оригинальные PDF/изображения/чертежи публично доступны по прямым статическим ссылкам. Страницы проверяют Supabase-сеанс, НО это не защита физических файлов. Для ограничения доступа к документам требуется отдельный защищённый storage и подписанные ссылки.
9. Старые виджеты сессий и жалоб, работающие через localStorage, в исходном script.js ещё присутствуют: они не синхронизируются между компьютерами. Новая админка читает complaints из Supabase, а старая форма жалобы нуждается в дополнительной интеграции до рабочего запуска.
10. Чтобы развернуть через Git Bash / Supabase CLI:
   supabase login
   supabase link --project-ref jqeztuwbzwqpetqnjenz
   supabase functions deploy site-api --no-verify-jwt
11. Начинайте тесты в отдельной ветке и тестовом окружении. Дополнительно требуется серверное ограничение попыток логина; без него массовый подбор паролей ограничивается только механизмами Supabase Auth.
12. Адрес и телефон поддержки меняются в site-contacts.js.

Проверка: 1) регистрация и письмо, 2) логин/выход/повторный вход, 3) права обычного пользователя, 4) админские действия, 5) блокировка во время сессии, 6) мобильная версия, 7) доступ к файлам по прямому URL.
