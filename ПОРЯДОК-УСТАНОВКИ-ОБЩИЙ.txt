Существующие изображения, DXF, PDF, .git и другие файлы должны остаться в репозитории.
НЕТ подтверждения работы интеграции в реальном Supabase. Не публикуйте без тестов.

ПОРЯДОК:
1. Сделать резервную копию рабочей папки Git-проекта.
2. Распаковать архив. Скопировать СОДЕРЖИМОЕ папки factory-system в КОРЕНЬ Git-проекта (где index.html).
3. Открыть Supabase > SQL Editor. Выполнить supabase/ШАГ-2-ЗАЩИТА-ВХОДА.sql.
   Предыдущий SQL (supabase_step1.sql) уже выполнен. Не нужно запускать его повторно.
4. Supabase > Edge Functions > site-api > Code: заменить код полным содержимым
   supabase/functions/site-api/index.ts. Нажать Deploy.
5. Проверить функцию: HTTP POST; тело {"action":"health_check"}; заголовок Content-Type: application/json.
   Ожидаемый результат 401 с текстом «Авторизуйтесь».
6. Убедиться, что Verify JWT with legacy secret выключен. Это НЕ убирает проверку
   JWT для админских запросов внутри функции.
7. Не выполнять git push, пока не проверена регистрация с подтверждением почты,
   вход и запрет доступа без авторизации. Для тестирования используйте отдельный
   стенд/ветку, если возможно.
8. Первый администратор: создать собственный аккаунт через регистрацию и подтвердить
   email; в SQL Editor выполнить:
      update public.profiles set role='admin' where login='ВАШ_ЛОГИН';
   Выполнить ТОЛЬКО после проверки профиля и ТОЛЬКО для собственного логина.
9. Контактные данные: site-contacts.js, заменить прочерки для phone и website.
10. Если в Git остался netlify.toml, удалить отдельно.

ОГРАНИЧЕНИЯ/РИСКИ:
* Автоматический перенос старых локальных пользователей отключён: нельзя доказывать
  владение аккаунтом только JavaScript-данными из браузера. Старые данные не удаляются.
* Лимит входа: 5 запросов на один логин за 15 минут. Это базовая защита,
  не полноценная антибот-система; возможна временная блокировка логина при атаке.
* Статичные документы в публичной папке хостинга остаются доступны по прямой ссылке.
  Авторизация страниц сама по себе не защищает PDF и DXF от прямых URL.
* Блокировки действуют на проверяемых серверных операциях. Существующие сессии
  и публичные файлы требуют отдельной проверки защиты перед релизом.
* Настройки CORS разрешают https://kl1huq.sourcecraft.site; при смене домена их
  нужно обновить в Edge Function.
